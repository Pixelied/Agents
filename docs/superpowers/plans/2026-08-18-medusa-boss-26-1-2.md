# Medusa Boss 26.1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Minecraft Java 26.1.2 datapack-driven Medusa temple/labyrinth, multiplayer boss encounter, gaze/petrification and rescue mechanics, renewable rematch ritual, and 64-charge Medusa Staff, with a fully optional visual resource pack.

**Architecture:** The implementation lives under `projects/medusa-26-1-2` and follows the working Fallen Knight project pattern: vanilla datapack logic owns gameplay, marker-backed encounter instances own independent state, and an optional resource pack/ETF/EMF layer owns presentation. The temple is generated from a fixed checked-in ASCII layout into deterministic `fill`/`setblock` mcfunction output, avoiding binary structure-authoring dependencies while keeping the labyrinth handcrafted. High-frequency gaze and staff logic runs only for active participants/active staff users and uses stable score-backed IDs plus explicit cleanup/recovery paths.

**Tech Stack:** Minecraft Java 26.1.2 datapacks; Java 25 dedicated server; datapack format 101.1; resource-pack format 84.0; mcfunction macros/storage; Python 3 standard-library generators and contract tests; GitHub Actions exact-runtime smoke validation; optional ETF/EMF presentation.

**Spec:** `docs/superpowers/specs/2026-08-18-medusa-boss-26-1-2-design.md`

## Scope Check

The temple, arena state machine, gaze/petrification, Medusa attacks, rewards, rematch ritual, and staff all share the same canonical item IDs and encounter-instance contract. They are therefore one integrated shippable feature rather than independent products. The plan keeps them in one implementation stream but splits work at independently testable boundaries.

## Global Constraints

- Target exactly Minecraft Java **26.1.2** and validate with Java **25**.
- Datapack `min_format`/`max_format` are `[101, 1]`; resource-pack `min_format`/`max_format` are `[84, 0]`.
- Gameplay must remain correct with the resource pack and ETF/EMF disabled.
- Each temple is an independent instance; boss, puzzle, participant, Eye, reward, staff-helper, and cleanup selectors must be instance-scoped.
- The dungeon is fixed/handcrafted with optional branches and exactly three required Gorgon-themed puzzles; do not add procedural maze generation.
- The Golden Gorgon Eye uses the approved black-and-gold head texture and remains a persistent rematch key.
- Boss phases are 100–60%, below 60%, and below 28%; phase transitions are about 5 seconds and one-shot.
- Boss gaze petrification uses 0–1000 fixed-point units where 1000 = 100%: normal gaze +12 units per 0.1 s, empowered gaze +55 units per 0.1 s, decay -20 units per 0.1 s after a 0.5 s delay.
- Full boss petrification starts custom suffocation after 1 second at 2 health points per second and uses a 12-point teammate rescue shell.
- Medusa Staff capacity is exactly **64 charges**; one Gorgon Scale restores **8**; Stone Spikes costs **4**; channel pre-pays one charge per one-second segment and fully petrifies at about 3 seconds.
- Staff channel interruption must support LOS break, aim-lock loss, caster damage, and heavy caster movement reduction.
- Staff-petrified normal mobs/players auto-release after about 5 seconds; boss-class targets auto-release after about 1.5 seconds and never receive the staff suffocation finisher.
- Stone Spikes never permanently edits terrain.
- Do not add the future cross-boss Golden Gorgon Eye recipe.
- Natural worldgen is intentionally outside this first implementation. Admin placement creates instances through `medusa:admin/place_temple`; later worldgen must be able to call the same `medusa:instance/register` contract.

## Canonical State and IDs

Use these names consistently across all tasks:

- `md_eid` — encounter/temple instance ID.
- `md_aid` — stable player/actor ID where an owner link is needed.
- `md_tid` — lazily assigned staff target ID.
- `md_state` — instance state: `0 sealed`, `1 awakening`, `2 active`, `3 defeated`, `4 ritual_ready`, `5 resetting`.
- `md_phase` — Medusa phase 1/2/3.
- `md_petr` — player/boss-gaze petrification fixed point, 0–1000.
- `md_pct` — displayed integer percent, 0–100.
- `md_shell` — rescue progress, 0–12.
- `md_staff` — current held staff charge count, 0–64.
- `md_lock` — staff channel target ID.
- `md_use` — staff channel tick counter.
- `md_rewarded` — one-shot boss reward guard on the instance anchor.
- `medusa:macro` — namespaced macro/storage scratch context; never persistent source of truth.
