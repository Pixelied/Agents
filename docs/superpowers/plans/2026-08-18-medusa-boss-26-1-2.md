# Medusa Boss 26.1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Minecraft Java 26.1.2 datapack-driven Medusa temple, labyrinth, multiplayer boss encounter, petrification/rescue system, renewable ritual, and charged Medusa Staff with an optional swappable visual resource pack.

**Architecture:** The implementation lives in `projects/medusa-26-1-2` and follows the proven Fallen Knight pattern: a vanilla datapack owns all gameplay, independent marker-backed encounter instances own state, and an optional resource pack/ETF/EMF layer owns presentation. A deterministic text generator builds the fixed temple/labyrinth from a checked-in map so the dungeon stays reproducible and testable without binary structure-template authoring. High-frequency gaze and staff logic runs only for active participants and uses score-backed IDs, macros/storage, and explicit cleanup paths.

**Tech Stack:** Minecraft Java 26.1.2 datapacks, Java 25 dedicated server, datapack format 101.1, resource-pack format 84.0, mcfunction macros/storage, Python 3 standard-library contract tests/generators, GitHub Actions exact-runtime validation, optional ETF/EMF resource-pack presentation.

**Spec:** `docs/superpowers/specs/2026-08-18-medusa-boss-26-1-2-design.md`

## Global Constraints

- Target exactly Minecraft Java **26.1.2** and validate with Java **25**.
- Datapack `min_format`/`max_format` are `[101, 1]`; resource-pack `min_format`/`max_format` are `[84, 0]`.
- Gameplay must remain correct with the resource pack and ETF/EMF disabled.
- Each temple is an independent instance; no global boss, puzzle, participant, Eye, or cleanup state may leak between instances.
- The dungeon is a fixed handcrafted critical route with optional branches and exactly three simple required Gorgon-themed puzzles; do not add procedural labyrinth generation.
- The Golden Gorgon Eye uses the approved black-and-gold head texture value and is a persistent ritual key, not a consumed one-time artifact.
- Medusa has three phases at 100–60%, below 60%, and below 28%; transitions are about 5 seconds and one-shot.
- Petrification is per player, 0–100%, with normal gaze at 12 points/second, 0.5-second decay delay, 20 points/second decay, and Gorgon Gaze at 55 points/second after a 1.75-second telegraph.
- Full boss petrification starts custom suffocation after 1 second at 2 health points/second; teammates rescue through a 12-point Stone → Cracked → Shattered shell.
- Medusa Staff capacity is exactly **64 charges**; one Gorgon Scale restores **8**; Stone Spikes costs **4**; channeling costs about **1 charge/second** and reaches full petrification at about 3 seconds.
- Staff channel counterplay is mandatory: line-of-sight break, caster damage, or aim-lock loss interrupts; the caster is heavily movement-limited while channeling.
- Normal mobs/players remain fully petrified about 5 seconds after a completed channel; boss-class targets crack free after about 1.5 seconds and cannot be killed by the staff suffocation finisher.
- Stone Spikes must not permanently grief terrain.
- Do not implement the future cross-boss Golden Gorgon Eye recipe in this project.
- Natural world-generation integration is not added in this first implementation; temple instances are created by an explicit admin placement function. The instance architecture must allow later worldgen to register the same anchor contract without rewriting boss logic.

`projects/medusa-26-1-2/resourcepacks/medusa/` contains optional Medusa/serpent/statue/item visuals and EMF/ETF rules. The selected dark teal/green Medusa skin becomes `assets/medusa/textures/entity/medusa_base.png` during the visual task.

- [ ] **Step 3: Implement Averted Eyes and Borrowed Gaze as button-driven finite-state puzzles**

Averted Eyes has three orientation scores 0–3. Each button rising edge advances one score modulo 4 and rotates the associated statue display. The solved tuple is `(1, 3, 2)`. A wrong submit flashes the idol, plays a hostile hiss, and spawns two temporary snake carriers; it never resets other puzzles.

Borrowed Gaze has two mirror scores 0–3. The solved tuple is `(2, 1)`. Draw a short dust-particle beam matching each current orientation so players can read the puzzle without text instructions.

- [ ] **Step 4: Implement Blind Passage and final progression**

Blind Passage cycles four wall-eye zones every 20 ticks. The fixed cover columns built by Task 2 define safe sections. A player in the currently exposed zone receives Slowness, stone particles, and is moved back to that passage's start marker; the sequence then continues. Reaching the final trigger area sets `md_p3_done=1`.

`puzzle/complete.mcfunction` sets `md_dungeon_clear=1` only when all three required puzzle scores are complete, opens the final gate, and never closes it on future rematches.
